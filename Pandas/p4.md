# Pandas — Part 4: `merge()`, `join()`, `concat()`

Now we're going to learn something **extremely important for real-world data**:

> **How do I combine datasets?**

In real ML projects, you almost never get everything in one perfect CSV.

You might have:

```text
customers.csv
orders.csv
payments.csv
locations.csv
```

and need to combine them.

This is where:

```text
merge()
join()
concat()
```

come in.

The most important one is **`merge()`**.

---

# 1. Real-World Scenario

Imagine an online store.

You have one table containing customers:

```text
Customer_ID    Name       City
--------------------------------
101            Ali        Karachi
102            Sara       Lahore
103            Ahmed      Islamabad
104            Zain       Karachi
```

And another table containing their orders:

```text
Order_ID    Customer_ID    Amount
-----------------------------------
1           101             5000
2           102             3000
3           101             7000
4           104             2500
```

Notice something important:

The tables don't have the same columns.

But they share:

```text
Customer_ID
```

That is our **key**.

We can use it to combine them.

---

# 2. Create the DataFrames

```python
import pandas as pd

customers = pd.DataFrame({
    "Customer_ID": [101, 102, 103, 104],
    "Name": ["Ali", "Sara", "Ahmed", "Zain"],
    "City": ["Karachi", "Lahore", "Islamabad", "Karachi"]
})

orders = pd.DataFrame({
    "Order_ID": [1, 2, 3, 4],
    "Customer_ID": [101, 102, 101, 104],
    "Amount": [5000, 3000, 7000, 2500]
})
```

---

# 3. `merge()`

We can combine them:

```python
df = pd.merge(
    customers,
    orders,
    on="Customer_ID"
)
```

Result:

```text
Customer_ID   Name    City       Order_ID   Amount
---------------------------------------------------
101           Ali     Karachi       1        5000
101           Ali     Karachi       3        7000
102           Sara    Lahore        2        3000
104           Zain    Karachi       4        2500
```

Look carefully.

Customer `101` appears **twice** because Ali made two orders.

This is exactly what we wanted.

---

# 4. Understand What Happened

Think of it like this:

```text
CUSTOMERS

Customer_ID
     │
     ├── 101 → Ali
     ├── 102 → Sara
     ├── 103 → Ahmed
     └── 104 → Zain


ORDERS

Customer_ID
     │
     ├── 101 → Order 1
     ├── 102 → Order 2
     ├── 101 → Order 3
     └── 104 → Order 4
```

Pandas says:

> Find matching `Customer_ID`s and combine their information.

This is essentially the same idea as a **SQL JOIN**.

---

# 5. Why Ahmed Disappeared

Notice:

```text
Ahmed → Customer_ID 103
```

doesn't appear in the result.

Why?

Because Ahmed has no order.

Our default merge is:

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID"
)
```

which performs an:

# Inner Join

Only matching records survive.

---

# 6. The Four Important Join Types

You should know these:

```text
inner
left
right
outer
```

These are directly related to SQL joins.

---

# 7. Inner Join

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    how="inner"
)
```

Meaning:

> Keep only IDs that exist in **both** tables.

Visualize:

```text
Customers        Orders

101 ──────────── 101  ✓
102 ──────────── 102  ✓
103             103?  ✗
104 ──────────── 104  ✓
```

Result:

```text
101
102
104
```

---

# 8. Left Join ⭐

Now suppose you want:

> Keep **every customer**, even if they haven't ordered anything.

Use:

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    how="left"
)
```

Result:

```text
Customer_ID   Name    City        Order_ID   Amount
----------------------------------------------------
101           Ali     Karachi       1        5000
101           Ali     Karachi       3        7000
102           Sara    Lahore        2        3000
103           Ahmed   Islamabad     NaN       NaN
104           Zain    Karachi       4        2500
```

Ahmed is now included.

Why?

Because the **left table** is `customers`.

---

# 9. Mental Trick for `how`

When you see:

```python
pd.merge(
    A,
    B,
    how="left"
)
```

think:

> **"Keep everything from A."**

For:

```python
how="right"
```

think:

> **"Keep everything from B."**

For:

```python
how="inner"
```

think:

> **"Keep only matches."**

For:

```python
how="outer"
```

think:

> **"Keep everything from both."**

---

# 10. Right Join

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    how="right"
)
```

This keeps every row from `orders`.

So if an order references a customer that isn't in the customer table, that order still remains.

This can be useful for investigating data inconsistencies.

---

# 11. Outer Join

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    how="outer"
)
```

This keeps everything from both tables.

Conceptually:

```text
CUSTOMERS
101
102
103
104

ORDERS
101
102
104
105
```

Outer join gives:

```text
101
102
103
104
105
```

Missing information becomes `NaN`.

---

# 12. The Best Visual Memory

Remember:

```text
              INNER
         ┌─────────────┐
         │   A ∩ B     │
         └─────────────┘

              LEFT
         ┌─────────────┐
         │     A       │
         │   + match   │
         └─────────────┘

             RIGHT
         ┌─────────────┐
         │     B       │
         │   + match   │
         └─────────────┘

             OUTER
         ┌─────────────┐
         │   A ∪ B     │
         └─────────────┘
```

The most important distinction:

```text
inner → intersection
outer → union
left  → preserve left
right → preserve right
```

---

# 13. `concat()`

Now let's look at another operation.

Suppose you have:

```text
January sales
February sales
March sales
```

Each file has the **same columns**:

```text
Date
Product
Sales
```

You don't want to join them based on an ID.

You want to **stack them**.

That's `concat()`.

---

# 14. Example

```python
jan = pd.DataFrame({
    "Product": ["Laptop", "Phone"],
    "Sales": [100000, 50000]
})

feb = pd.DataFrame({
    "Product": ["Tablet", "Phone"],
    "Sales": [40000, 60000]
})
```

Combine them:

```python
sales = pd.concat(
    [jan, feb]
)
```

Result:

```text
Product    Sales
----------------
Laptop     100000
Phone       50000
Tablet      40000
Phone       60000
```

Think:

```text
JANUARY
   ↓
FEBRUARY
   ↓
MARCH
   ↓
CONCAT
   ↓
ONE BIG TABLE
```

---

# 15. `concat()` vs `merge()`

This distinction is **very important**.

### `concat()`

Usually means:

> **Stack datasets.**

```text
A
B
C

↓

A
B
C
```

### `merge()`

Usually means:

> **Combine datasets using a key.**

```text
Customer_ID
     ↓
Customers + Orders
```

Think:

```text
concat → stacking
merge  → matching
```

---

# 16. Vertical Concatenation

By default:

```python
pd.concat([df1, df2])
```

stacks rows.

Example:

```text
df1

A   B
1   2
3   4

df2

A   B
5   6
7   8
```

Result:

```text
A   B
1   2
3   4
5   6
7   8
```

---

# 17. Horizontal Concatenation

You can also concatenate columns:

```python
pd.concat(
    [df1, df2],
    axis=1
)
```

Conceptually:

```text
df1        df2

A  B       C  D
1  2       5  6
3  4       7  8
```

becomes:

```text
A  B  C  D
1  2  5  6
3  4  7  8
```

So:

```text
axis=0 → stack rows
axis=1 → place columns side-by-side
```

Same NumPy/Pandas axis concept you've already learned.

---

# 18. `ignore_index=True`

After concatenating:

```python
pd.concat([jan, feb])
```

you might get:

```text
0
1
0
1
```

because each original DataFrame had its own index.

Usually you want a fresh index:

```python
pd.concat(
    [jan, feb],
    ignore_index=True
)
```

Result:

```text
0
1
2
3
```

This is commonly used.

---

# 19. Merging on Different Column Names

Sometimes your keys have different names.

For example:

```text
customers:

customer_id

orders:

cust_id
```

You can't simply do:

```python
on="customer_id"
```

because the names differ.

Use:

```python
pd.merge(
    customers,
    orders,
    left_on="customer_id",
    right_on="cust_id"
)
```

Meaning:

```text
customers.customer_id
          ↕
orders.cust_id
```

---

# 20. Merging on Multiple Columns

Sometimes one column isn't enough to uniquely identify a match.

Suppose:

```text
Student_ID
Course_ID
```

together identify a record.

Then:

```python
pd.merge(
    df1,
    df2,
    on=["Student_ID", "Course_ID"]
)
```

means:

> Match when **both** columns match.

This is common in relational datasets.

---

# 21. A Very Important Problem: Duplicate Keys

This is something beginners often don't realize.

Suppose:

```text
customers

Customer_ID   Name
101           Ali
102           Sara
```

and:

```text
orders

Customer_ID   Order
101           A
101           B
101           C
```

After merging:

```text
101   Ali   A
101   Ali   B
101   Ali   C
```

One customer becomes three rows.

That's not Pandas making a mistake.

It's because:

```text
1 customer
     ↓
3 orders
```

So the relationship is:

```text
ONE → MANY
```

---

# 22. Many-to-Many Can Explode

Suppose table A contains:

```text
ID
1
1
```

and table B contains:

```text
ID
1
1
```

Merging them can produce:

```text
A1 × B1
A1 × B2
A2 × B1
A2 × B2
```

That's:

```text
2 × 2 = 4 rows
```

This is called a **many-to-many merge**.

With large datasets, this can cause a massive row explosion.

So always understand the relationship between your tables before merging.

---

# 23. Validate Your Merge

Pandas can help you catch incorrect assumptions.

For example:

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    validate="one_to_many"
)
```

This says:

> I expect one customer to have many orders.

If your data violates that expectation, Pandas can raise an error.

Possible relationships include:

```text
one_to_one
one_to_many
many_to_one
many_to_many
```

This is very useful in serious data work.

---

# 24. Handling Same Column Names

Suppose both datasets have:

```text
Name
```

After merging, Pandas may create:

```text
Name_x
Name_y
```

You can control the suffixes:

```python
pd.merge(
    df1,
    df2,
    on="ID",
    suffixes=("_customer", "_order")
)
```

Now you might get:

```text
Name_customer
Name_order
```

Much clearer.

---

# 25. `join()`

Pandas also has:

```python
df.join()
```

`join()` is particularly convenient when you're combining data based on the **index**.

For example:

```python
df1.join(df2)
```

If:

```text
df1 index = Customer_ID
df2 index = Customer_ID
```

then they can be joined based on that index.

For beginners, I'd recommend thinking:

```text
merge() → general-purpose key-based combination
join()  → convenient index-based combination
concat() → stacking
```

In practice, you'll probably use `merge()` much more often than `join()` at first.

---

# 26. SQL ↔ Pandas Connection

Since you may encounter SQL in ML/data engineering, make this connection.

### SQL

```sql
SELECT *
FROM customers
INNER JOIN orders
ON customers.Customer_ID = orders.Customer_ID;
```

### Pandas

```python
pd.merge(
    customers,
    orders,
    on="Customer_ID",
    how="inner"
)
```

Very similar concept.

Think:

```text
SQL JOIN
   ↕
Pandas merge()
```

This is extremely useful knowledge.

# 27. Real ML Example

Imagine you're building a model to predict whether a customer will purchase a product.

You have:

### Customer table

```text
Customer_ID
Age
City
Income
```

### Purchase table

```text
Customer_ID
Product
Amount
Date
```

### Website activity

```text
Customer_ID
Pages_Viewed
Time_On_Site
Cart_Items
```

You might combine:

```python
df = pd.merge(
    customers,
    purchases,
    on="Customer_ID",
    how="left"
)
```

Then:

```python
df = pd.merge(
    df,
    website_activity,
    on="Customer_ID",
    how="left"
)
```

Now you have a much richer dataset:

```text
Customer_ID
Age
City
Income
Product
Amount
Date
Pages_Viewed
Time_On_Site
Cart_Items
```

This is much closer to what an ML dataset looks like.

---

# 28. But There's a Major ML Problem Here

Suppose we're predicting:

> Will the customer purchase tomorrow?

And our website activity table contains data from:

```text
tomorrow
```

Then we're accidentally giving the model future information.

That's **data leakage**.

For example:

```text
Prediction time
      │
      ↓
Customer features
      │
      ↓
      MODEL
      │
      ↓
Purchase tomorrow
```

Features must generally represent information available **at prediction time**.

Not:

```text
future information
```

This is why combining datasets isn't just a technical operation.

You must understand the **meaning and timing of the data**.

# 31. A Small Exercise

Let's say we have:

```python
students = pd.DataFrame({
    "Student_ID": [1, 2, 3, 4],
    "Name": ["Ali", "Sara", "Ahmed", "Zain"],
    "City": ["Karachi", "Lahore", "Karachi", "Islamabad"]
})

marks = pd.DataFrame({
    "Student_ID": [1, 2, 1, 4],
    "Subject": ["Math", "Math", "Physics", "Math"],
    "Marks": [85, 90, 78, 65]
})
```

Try to answer:

### A

How would you combine them so that every student with marks appears?

Think:

```text
students + marks
```

### B

How would you keep **all students**, even those without marks?

### C

How would you stack two DataFrames that have identical columns?

### D

How would you merge two DataFrames when their key columns have different names?

Answers:

```python
# A
pd.merge(
    students,
    marks,
    on="Student_ID",
    how="inner"
)

# B
pd.merge(
    students,
    marks,
    on="Student_ID",
    how="left"
)

# C
pd.concat(
    [df1, df2],
    ignore_index=True
)

# D
pd.merge(
    df1,
    df2,
    left_on="student_id",
    right_on="id"
)
```

# 32. The Three Functions You Must Remember

If you only remember three things from this lesson:

## `merge()` → MATCH

```python
pd.merge(
    df1,
    df2,
    on="ID"
)
```

Use when:

> "These datasets contain related information and share a key."

---

## `concat()` → STACK

```python
pd.concat(
    [df1, df2],
    ignore_index=True
)
```

Use when:

> "These datasets have similar structures and I want to put them together."

---

## `join()` → INDEX

```python
df1.join(df2)
```

Use when:

> "I want to combine data using indexes."

---

# 33. The Mental Picture

Burn this into your memory:

```text
                 COMBINING DATA
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       merge()      concat()      join()
          │            │            │
          ↓            ↓            ↓
       MATCH         STACK         INDEX
          │            │            │
          ↓            ↓            ↓
       key/ID       rows/cols     index
```

And for `merge()`:

```text
               MERGE
                 │
       ┌─────────┼─────────┐
       ↓         ↓         ↓
     inner      left      outer
       │         │         │
     match    keep A     keep A+B
```
