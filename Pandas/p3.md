# Pandas — Part 3: `groupby()`, Aggregation, `agg()`, `transform()`, `apply()`

Now we're getting into **one of the most powerful parts of Pandas**.

So far you've learned how to look at and clean individual rows/columns.

Now we'll learn how to ask questions like:

> "What is the average salary for each department?"

> "Which city has the highest average salary?"

> "How many employees work in each department?"

> "What is each employee's salary compared to their department's average?"

These are **group-based questions**, and `groupby()` is the tool for them.

---

# 1. The Big Idea

Imagine this dataset:

```text
Employee   Department     Salary
----------------------------------
Ali        Engineering    100000
Sara       Engineering    120000
Ahmed      Sales           70000
Zain       Sales           80000
Hina       HR              60000
Usman      HR              65000
```

Suppose we ask:

> What is the average salary in each department?

You could manually calculate:

```text
Engineering:
(100000 + 120000) / 2 = 110000

Sales:
(70000 + 80000) / 2 = 75000

HR:
(60000 + 65000) / 2 = 62500
```

But imagine having:

```text
10 million employees
```

You don't want to manually calculate this.

Pandas:

```python
df.groupby("Department")["Salary"].mean()
```

does it for you.

---

# 2. The Mental Model

This is the most important thing to understand.

When you write:

```python
df.groupby("Department")
```

Pandas conceptually does:

```text
                 DATAFRAME
                     │
                     ↓
             Group by Department
                     │
        ┌────────────┼────────────┐
        ↓            ↓            ↓
 Engineering       Sales          HR
    │                │             │
 Ali, Sara       Ahmed, Zain    Hina, Usman
```

Then you perform some operation on each group:

```text
mean()
sum()
count()
min()
max()
...
```

So:

```text
groupby()
   ↓
Split data into groups
   ↓
Perform operation on each group
   ↓
Combine results
```

This is called:

# Split → Apply → Combine

# 4. Basic `groupby()`

Let's group employees by department:

```python
df.groupby("Department")
```

You won't immediately see the useful result.

That's because we've only said:

> "Create groups."

We haven't told Pandas what to calculate.

---

# 5. Group + Mean

Let's calculate average salary:

```python
df.groupby("Department")["Salary"].mean()
```

Result:

```text
Department
Engineering    110000
HR              75000
Sales           78333
```

Conceptually:

```text
Engineering
    ↓
80000
120000
130000
    ↓
mean
    ↓
110000
```

---

# 6. Group + Sum

Want total salary paid by each department?

```python
df.groupby("Department")["Salary"].sum()
```

For example:

```text
Engineering    330000
HR             150000
Sales          235000
```

So:

```text
mean() → average
sum()  → total
```

---

# 7. Group + Count

How many employees are in each department?

```python
df.groupby("Department")["Employee"].count()
```

Result:

```text
Engineering    3
HR             2
Sales          3
```

---

# 8. `size()` vs `count()`

You may also see:

```python
df.groupby("Department").size()
```

This counts rows in each group.

Why does that matter?

Because `count()` generally counts **non-missing values** in the selected column.

Suppose:

```text
Department    Salary
Engineering   100000
Engineering   NaN
```

Then:

```python
df.groupby("Department")["Salary"].count()
```

could return:

```text
Engineering → 1
```

while:

```python
df.groupby("Department").size()
```

returns:

```text
Engineering → 2
```

So:

```text
count() → non-missing values
size()  → rows
```

# 9. Group + Maximum

Highest salary in each department:

```python
df.groupby("Department")["Salary"].max()
```

# 10. Group + Minimum

Lowest salary:

```python
df.groupby("Department")["Salary"].min()
```

# 11. Group + Multiple Statistics

Now things get interesting.

Suppose you want:

```text
minimum salary
maximum salary
average salary
```

You can use:

```python
df.groupby("Department")["Salary"].agg(
    ["min", "max", "mean"]
)
```

Result conceptually:

```text
              min      max      mean
Engineering   80000   130000   110000
HR            65000    85000    75000
Sales         70000    90000    78333
```

This is much more useful than running three separate operations.

---

# 12. What is `agg()`?

`agg` means:

> **Aggregate**

It allows you to perform multiple calculations.

For example:

```python
df["Salary"].agg(["mean", "min", "max"])
```

gives:

```text
mean
min
max
```

With grouping:

```python
df.groupby("Department")["Salary"].agg(
    ["mean", "min", "max"]
)
```

means:

> For each department, calculate mean, minimum, and maximum salary.

---

# 13. Different Aggregations for Different Columns

Suppose we want:

```text
Salary:
    mean
    max

Experience:
    mean
    max
```

We can write:

```python
df.groupby("Department").agg({
    "Salary": ["mean", "max"],
    "Experience": ["mean", "max"]
})
```

This is a very common Pandas pattern.

---

# 14. Named Aggregations

There's an even cleaner approach.

```python
df.groupby("Department").agg(
    average_salary=("Salary", "mean"),
    maximum_salary=("Salary", "max"),
    average_experience=("Experience", "mean")
)
```

Result:

```text
              average_salary   maximum_salary   average_experience
Engineering       110000          130000              4.33
HR                 75000           85000              7.00
Sales              78333           90000              3.33
```

This is extremely readable.

You are basically saying:

```text
Create column:
average_salary

using:
Salary

with:
mean
```

# 15. Why `groupby()` Matters in ML

Suppose you're predicting house prices.

Dataset:

```text
City       Size    Bedrooms    Price
-------------------------------------

Karachi    1500      3        18M
Lahore     1200      3        12M
Lahore     1800      4        20M
```

You might ask:

> What's the average house price by city?

```python
df.groupby("City")["Price"].mean()
```

That gives you valuable information about the dataset.

This is called **exploratory data analysis (EDA)**.

Pandas is heavily used for EDA before ML.

```text
    ├── Karachi

    ├── Karachi
    ├── Lahore
    └── Islamabad
```

Pandas calculates the statistic for every combination.

# 20. Now Meet `transform()`

This is one of the most important concepts to understand.

Suppose:

```text
Employee    Department    Salary
Ali         Engineering   80000
Sara        Engineering   120000
Bilal       Engineering   130000
Ahmed       Sales         70000
Zain        Sales         90000
Ayesha      Sales         75000
```

We calculate:

```python
df.groupby("Department")["Salary"].mean()
```

We get:

```text
Engineering → 110000
Sales       → 78333
```

But what if we want to put the department average **beside every employee**?

We want:

```text
Employee   Department    Salary    Dept_Avg
Ali        Engineering   80000     110000
Sara       Engineering   120000    110000
Bilal      Engineering   130000    110000
Ahmed      Sales         70000      78333
Zain       Sales         90000      78333
Ayesha     Sales         75000      78333
```

That's where `transform()` comes in.

---

# 21. `transform("mean")`

```python
df["Dept_Avg_Salary"] = (
    df.groupby("Department")["Salary"]
      .transform("mean")
)
```

Now every row gets the average salary of its department.

This is a **huge concept**.

---

# 22. `groupby()` vs `transform()`

Remember this distinction:

### `groupby().mean()`

Reduces the data:

```text
Engineering → 110000
Sales       → 78333
```

### `groupby().transform("mean")`

Keeps the original number of rows:

```text
Ali     → 110000
Sara    → 110000
Bilal   → 110000
Ahmed   → 78333
Zain    → 78333
Ayesha  → 78333
```

Think:

```text
aggregate
    ↓
smaller result

transform
    ↓
same number of rows
```

This distinction is extremely important in feature engineering.

---

# 23. Real ML Feature Engineering Example

Suppose we're predicting employee performance.

We have:

```text
Salary
Department
```

We create:

```text
Department_Average_Salary
```

using:

```python
df["Dept_Avg_Salary"] = (
    df.groupby("Department")["Salary"]
      .transform("mean")
)
```

Then perhaps:

```python
df["Salary_vs_Department"] = (
    df["Salary"] /
    df["Dept_Avg_Salary"]
)
```

Now:

```text
Salary_vs_Department = 1.0
```

means:

> This employee earns approximately the department average.

While:

```text
1.2
```

means:

> This employee earns about 20% more than the department average.

This is exactly the kind of **derived feature** you can create using Pandas.

# 24. `transform()` With Other Operations

You aren't limited to mean.

You can do:

```python
df.groupby("Department")["Salary"].transform("max")
```

or:

```python
df.groupby("Department")["Salary"].transform("min")
```

or:

```python
df.groupby("Department")["Salary"].transform("median")
```

# 25. Group-Level Standardization

Here's a more interesting ML example.

Suppose salaries differ greatly between departments.

Maybe:

```text
Engineering → naturally higher salaries
HR          → naturally lower salaries
```

We might calculate how far an employee's salary is from their department's average.

One simple feature:

```python
df["Salary_Difference"] = (
    df["Salary"] -
    df.groupby("Department")["Salary"].transform("mean")
)
```

Now:

```text
positive → above department average
negative → below department average
```

This can be useful in certain ML problems.

# 26. `apply()`

Now we reach another important function:

```python
apply()
```

It lets you apply a custom function to data.

For example:

```python
def salary_category(salary):
    if salary >= 100000:
        return "High"
    elif salary >= 70000:
        return "Medium"
    else:
        return "Low"
```

Then:

```python
df["Salary_Category"] = df["Salary"].apply(
    salary_category
)
```

Now:

```text
Salary     Category
80000      Medium
120000     High
70000      Medium
90000      Medium
65000      Low
```

---

# 27. Lambda Functions

You can write small functions more compactly:

```python
df["Salary_Category"] = df["Salary"].apply(
    lambda x: "High" if x >= 100000 else "Low"
)
```

But don't rush to use `lambda` everywhere.

For beginners:

```python
def function(x):
    ...
```

is often easier to understand.

---

# 28. `apply()` vs Vectorized Operations

This is important.

Suppose you want:

```python
df["Salary"] / 12
```

Don't do:

```python
df["Salary"].apply(lambda x: x / 12)
```

Prefer:

```python
df["Salary"] / 12
```

Why?

Because Pandas/NumPy vectorized operations are generally more efficient and clearer.

So:

```text
Simple mathematical operation
        ↓
Vectorized operation ⭐

Complex custom logic
        ↓
apply()
```

This is a good rule.

---

# 29. Example Where `apply()` Makes Sense

Suppose you need a complicated classification:

```python
def classify_employee(row):

    if row["Experience"] >= 5 and row["Salary"] >= 100000:
        return "Senior High Earner"

    elif row["Experience"] >= 5:
        return "Senior"

    elif row["Salary"] >= 100000:
        return "High Earner"

    else:
        return "Junior"
```

You can apply it to rows:

```python
df["Category"] = df.apply(
    classify_employee,
    axis=1
)
```

Here:

```text
axis=1
```

means:

> Apply the function row-by-row.

---

# 30. Why `axis=1`?

The function receives one row at a time.

Conceptually:

```text
Row 0
 ↓
classify_employee()

Row 1
 ↓
classify_employee()

Row 2
 ↓
classify_employee()
```

Whereas:

```python
df.apply(function, axis=0)
```

works column-by-column.

Again:

```text
axis=0 → columns
axis=1 → rows
```

---

# 31. Important Performance Rule

You may see beginners write:

```python
df.apply(...)
```

for everything.

Don't.

For example:

```python
df["Age"] * 2
```

is preferable to:

```python
df["Age"].apply(lambda x: x * 2)
```

because Pandas/NumPy are designed for vectorized operations.

This becomes particularly important with millions of rows.

# 33. `pivot_table()`

Now let's introduce another powerful tool.

Suppose we have:

```text
Department    City          Salary
Engineering   Karachi       80000
Engineering   Lahore        120000
Sales         Karachi       70000
Sales         Lahore        90000
HR            Karachi       65000
```

We can create a spreadsheet-like summary:

```python
pd.pivot_table(
    df,
    values="Salary",
    index="Department",
    columns="City",
    aggfunc="mean"
)
```

Conceptually:

```text
City           Islamabad   Karachi   Lahore
Department
Engineering      130000      80000    120000
HR                            65000
Sales             75000      70000     90000
```

This is similar to a pivot table in Excel.

---

# 34. Why `pivot_table()`?

It's useful when you want to answer questions like:

> What is the average sales amount for each product category in each region?

Or:

> What is the average salary for each department in each city?

Or:

> How many customers belong to each age group in each city?

It is primarily an **analysis/summary tool**.

---

# 35. `groupby()` vs `pivot_table()`

Both can answer similar questions.

Think:

### `groupby()`

More programmatic:

```python
df.groupby(
    ["Department", "City"]
)["Salary"].mean()
```

### `pivot_table()`

More table-oriented:

```python
pd.pivot_table(
    df,
    values="Salary",
    index="Department",
    columns="City",
    aggfunc="mean"
)
```

Use whichever produces the structure you need.

# 38. One Subtle ML Issue: Leakage

There's an important warning here.

Suppose you're creating:

```python
df["Dept_Avg_Salary"]
```

for an ML model where `Salary` is the **target variable**.

That could cause leakage because you're using the target itself to construct a feature.

For example:

```text
Salary
  ↓
Department average Salary
  ↓
Feature
```

The feature contains information derived from the target.

That's potentially **target leakage**.

This is why feature engineering for ML requires careful thought.

We'll revisit this when we get to the ML-specific Pandas section.

Memorize the **patterns**.

```python
df.groupby("column")
```

```python
df["dept_avg"] = (
```

# 40. The Most Important Three to Understand

If you forget everything else from this lesson, remember these:

## `groupby()`

> **Divide data into groups.**

```python
df.groupby("Department")
```

## `agg()`

> **Calculate summary statistics for groups.**

```python
df.groupby("Department")["Salary"].agg(
    ["mean", "min", "max"]
)
```

## `transform()`

> **Calculate group statistics but put the result back onto every original row.**

```python
df["dept_avg"] = (
    df.groupby("Department")["Salary"]
      .transform("mean")
)
```

The difference:

```text
groupby + agg
       ↓
summary table

groupby + transform
       ↓
same original rows + new information
```

That distinction will become **very important when we start feature engineering for ML.**
