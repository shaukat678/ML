# Pandas for ML — Part 8: Missing Data & Imputation ⭐

Now we're entering a part of ML that looks simple but causes **a lot of mistakes in real projects**.

You will almost never encounter a perfectly clean dataset.

Real data looks more like:

```text
Age    Salary    City       Experience
----------------------------------------
21     50000     Karachi       2
25     NaN       Lahore        4
NaN    70000     Karachi       5
30     80000     NaN           7
27     NaN       Lahore        NaN
```

The `NaN`s are **missing values**.

Our job is to decide:

> What should we do when information is missing?

---

# 1. First: What Is `NaN`?

`NaN` means:

> **Not a Number**

But in Pandas, it is commonly used to represent missing data even when the column isn't necessarily numerical.

For example:

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "Age": [20, 25, np.nan, 30],
    "Salary": [50000, np.nan, 70000, 80000]
})
```

You'll see:

```text
    Age   Salary
0   20    50000
1   25      NaN
2   NaN    70000
3   30    80000
```

---

# 2. Why Does Missing Data Exist?

This is important.

Missing values aren't always caused by a programming mistake.

They can happen because:

### User didn't provide information

```text
Age = ?
```

### Sensor failed

```text
Temperature = NaN
```

### Database error

```text
Salary = NULL
```

### Information wasn't applicable

For example:

```text
Pregnancy_Status
```

may not apply to some records.

### Data collection changed

A survey may have started asking a question halfway through the study.

So:

> **Missingness itself can sometimes contain information.**

That's why we shouldn't automatically replace every missing value with zero.

---

# 3. Never Confuse Missing With Zero

Suppose:

```text
Study_Hours
```

contains:

```text
5
7
0
NaN
```

These mean different things.

```text
0
```

means:

> The student studied for zero hours.

While:

```text
NaN
```

means:

> We don't know how many hours they studied.

Therefore:

```text
0 ≠ missing
```

This is a very important data-cleaning principle.

---

# 4. Detect Missing Values

The first tool:

```python
df.isna()
```

You'll get something like:

```text
Age   Salary
False False
False True
True  False
False False
```

`True` means:

> This value is missing.

---

# 5. Count Missing Values

This is one of the most useful Pandas commands:

```python
df.isna().sum()
```

Example:

```text
Age       1
Salary    1
City      0
```

This tells you:

```text
Age → 1 missing
Salary → 1 missing
City → 0 missing
```

---

# 6. Calculate Missing Percentage

Counts are useful, but percentages are often more informative.

```python
missing_percentage = (
    df.isna().mean() * 100
)
```

For example:

```text
Age       2.5%
Salary    10.0%
City      0.3%
```

Now you have a better understanding of the problem.

---

# 7. Find Rows With Missing Data

Suppose you want all rows where **at least one value is missing**:

```python
df[df.isna().any(axis=1)]
```

Let's understand:

```text
axis=1
```

means:

> Look across each row.

So:

```python
df.isna().any(axis=1)
```

means:

> Does this row contain at least one missing value?

---

# 8. Find Completely Complete Rows

You can do:

```python
df[df.notna().all(axis=1)]
```

Meaning:

> Keep rows where every column has a value.

---

# 9. Three Main Strategies

When you encounter missing data, there are three broad options:

```text
Missing Data
     │
     ├── Delete it
     │
     ├── Fill it
     │
     └── Use a model/strategy to estimate it
```

Let's explore them.

---

# 10. Strategy 1 — Delete Rows

Pandas:

```python
df.dropna()
```

Suppose:

```text
Age   Salary
20    50000
25    NaN
NaN   70000
30    80000
```

After:

```python
df.dropna()
```

you get:

```text
Age   Salary
20    50000
30    80000
```

Rows containing missing values were removed.

---

# 11. Why Can Dropping Be Dangerous?

Suppose you have:

```text
1,000,000 rows
```

and only:

```text
1% missing
```

Dropping might be perfectly reasonable depending on context.

But imagine:

```text
1,000 rows
```

and:

```text
40% missing
```

Dropping rows could destroy a huge portion of your dataset.

So don't blindly do:

```python
df.dropna()
```

---

# 12. Drop Columns Instead

Suppose:

```text
Column A → 1% missing
Column B → 3% missing
Column C → 95% missing
```

Column C may be nearly useless.

You might consider removing it:

```python
df.drop(
    columns=["Column_C"]
)
```

But again:

> Missing percentage alone isn't enough.

The feature may have domain importance.

---

# 13. Strategy 2 — Imputation

Instead of deleting missing values, we can estimate them.

This is called:

# Imputation

Imagine:

```text
Age

20
21
NaN
23
22
```

We could estimate:

```text
NaN → 22
```

Now the dataset remains intact.

---

# 14. Mean Imputation

Suppose:

```text
Age

20
25
30
35
NaN
```

Mean:

$$
\frac{20+25+30+35}{4}=27.5
$$

So:

```text
NaN → 27.5
```

In Pandas:

```python
df["Age"] = df["Age"].fillna(
    df["Age"].mean()
)
```

---

# 15. But Mean Isn't Always Good

Imagine salaries:

```text
30k
35k
40k
45k
5,000k
NaN
```

That huge outlier:

```text
5,000k
```

will pull the mean upward.

So mean imputation could produce an unrealistic value.

This is why we often consider:

# Median

---

# 16. Median Imputation

Suppose:

```text
Salary

30k
35k
40k
45k
5000k
NaN
```

The median is much less affected by the extreme value.

You can do:

```python
df["Salary"] = df["Salary"].fillna(
    df["Salary"].median()
)
```

A useful rule of thumb:

```text
Approximately symmetric distribution
        ↓
      Mean

Skewed / outlier-heavy distribution
        ↓
      Median
```

But don't treat that as an absolute rule.

---

# 17. Mode Imputation

For categorical data:

```text
City

Karachi
Lahore
Karachi
NaN
Karachi
Islamabad
```

The most common category is:

```text
Karachi
```

That's the **mode**.

So:

```python
df["City"] = df["City"].fillna(
    df["City"].mode()[0]
)
```

Now:

```text
NaN → Karachi
```

---

# 18. Why `[0]`?

Because:

```python
df["City"].mode()
```

returns a Series.

For example:

```text
0    Karachi
dtype: object
```

We want the actual value:

```python
df["City"].mode()[0]
```

→

```text
Karachi
```

---

# 19. Forward Fill

Pandas also has:

```python
df["Temperature"].ffill()
```

This means:

> Use the previous known value.

Example:

```text
10
12
NaN
NaN
15
```

becomes:

```text
10
12
12
12
15
```

This can be useful in **time-series data** where nearby observations are meaningfully related.

But it should not be used blindly for ordinary tabular data.

---

# 20. Backward Fill

Similarly:

```python
df["Temperature"].bfill()
```

uses the next known value.

Example:

```text
10
NaN
NaN
15
```

becomes:

```text
10
15
15
15
```

Again, this is particularly relevant when observations have a meaningful order, such as time.

---

# 21. A Major Question:

## Should We Impute Before or After Train/Test Split?

This is **extremely important**.

Suppose:

```text
Age

20
25
30
NaN
40
```

You calculate:

```python
df["Age"].mean()
```

using the entire dataset **before splitting**.

You've allowed information from the future test set to influence your preprocessing.

That's data leakage.

---

# 22. Correct Approach

Do:

```text
Raw Dataset
     ↓
Train/Test Split
     ↓
    ┌──────────┐
    ↓          ↓
  Train       Test
    │           │
    ↓           │
calculate       │
mean/median     │
from train      │
    │           │
    ↓           ↓
impute train  impute test
              using TRAIN
              statistic
```

This is the correct mental model.

---

# 23. Example

Suppose:

### Training:

```text
20
25
30
NaN
```

Mean:

$$
\frac{20+25+30}{3}=25
$$

So training:

```text
20
25
30
25
```

Now test:

```text
35
NaN
40
```

You don't calculate the test mean.

You use:

```text
training mean = 25
```

So:

```text
35
25
40
```

This keeps the test set genuinely unseen.

---

# 24. Scikit-learn's `SimpleImputer`

In ML projects, you'll often use:

```python
from sklearn.impute import SimpleImputer
```

For numerical columns:

```python
imputer = SimpleImputer(
    strategy="median"
)
```

Then:

```python
X_train_imputed = imputer.fit_transform(
    X_train
)
```

And:

```python
X_test_imputed = imputer.transform(
    X_test
)
```

Notice again:

```text
TRAIN → fit_transform
TEST  → transform
```

Same principle as `StandardScaler`.

---

# 25. Available Strategies

`SimpleImputer` supports common strategies such as:

```text
mean
median
most_frequent
constant
```

For example:

```python
SimpleImputer(strategy="mean")
```

or:

```python
SimpleImputer(strategy="median")
```

or:

```python
SimpleImputer(strategy="most_frequent")
```

---

# 26. Constant Imputation

You can explicitly choose a value:

```python
SimpleImputer(
    strategy="constant",
    fill_value=0
)
```

This replaces missing values with:

```text
0
```

But remember our earlier lesson:

> Missing ≠ zero.

So using zero should have a meaningful interpretation.

---

# 27. Missing Indicator

Here's a very interesting idea.

Suppose:

```text
Income

50k
60k
NaN
80k
```

Maybe missingness itself is meaningful.

For example:

> People with very high incomes might be less likely to report their income.

If you simply replace:

```text
NaN → median
```

you lose the information that:

> This value was originally missing.

We can preserve that information with a **missing indicator**.

Conceptually:

```text
Income    Income_Missing
50000          0
60000          0
55000          1
80000          0
```

Now the model can potentially learn:

```text
"Was the income missing?"
```

separately from:

```text
"What is the estimated income?"
```

---

# 28. `SimpleImputer` Can Create an Indicator

For example:

```python
imputer = SimpleImputer(
    strategy="median",
    add_indicator=True
)
```

This allows the preprocessing system to retain missingness information.

---

# 29. Why This Is Useful

Consider a loan application.

Suppose:

```text
Annual_Income
```

is missing.

That could mean:

```text
Person forgot
```

or:

```text
Person refused
```

or:

```text
Person doesn't have stable income
```

Those situations may themselves correlate with the prediction target.

Therefore:

```text
missingness
```

can sometimes be predictive.

---

# 30. Missingness Mechanisms

At a more advanced level, statisticians distinguish different types of missingness.

You'll hear:

```text
MCAR
MAR
MNAR
```

### MCAR

**Missing Completely At Random**

Missingness has no relationship with observed or unobserved data.

### MAR

**Missing At Random**

Missingness depends on information that is observed.

### MNAR

**Missing Not At Random**

Missingness itself depends on the missing/unobserved value or related unobserved factors.

You don't need to master these yet, but recognize the terms.

# 31. A Real Example

Imagine a medical dataset:

```text
Age
Blood Pressure
Weight
Cholesterol
Disease
```

Suppose cholesterol is missing more often among certain patients.

Simply doing:

```python
fillna(mean)
```

might hide important structure.

This is why:

> **Data cleaning isn't just mechanical. You need to understand why the data is missing.**

---

# 32. Group-Based Imputation

Sometimes the global mean isn't appropriate.

Suppose:

```text
Department    Salary
Physics       80k
Physics       NaN
Physics       90k
CS            150k
CS            NaN
CS            170k
```

Using the overall mean might be poor.

Instead, you could calculate the median **within each department**.

Conceptually:

```text
Physics → Physics median
CS      → CS median
```

This can preserve group structure.

Pandas is particularly useful for such operations.

---

# 33. Example With `groupby`

You might encounter patterns such as:

```python
df["Salary"] = (
    df.groupby("Department")["Salary"]
      .transform(lambda x: x.fillna(x.median()))
)
```

This says:

> For each department, replace missing salary values with that department's median salary.

Notice how `transform()` returns values aligned with the original DataFrame.

That's an important Pandas concept.

---

# 34. But Be Careful

Group-based imputation can also leak information if the grouping statistics are calculated using data that shouldn't be available at that stage.

In proper ML workflows:

```text
training data
    ↓
learn imputation rules
    ↓
apply to validation/test
```

The general principle never changes.

# 36. Complete Preprocessing Architecture

Your ML preprocessing can now look like:

```text
                         X
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
        NUMERICAL                CATEGORICAL
              │                     │
              ↓                     ↓
          Imputation             Imputation
          (median)               (most frequent)
              │                     │
              ↓                     ↓
        StandardScaler        OneHotEncoder
              │                     │
              └──────────┬──────────┘
                         ↓
                  ColumnTransformer
                         ↓

```

This is a very realistic ML preprocessing pipeline.

# 37. Putting It Into Code

Suppose:

```python
numeric_features = [
    "Age",
    "Income"
]

categorical_features = [
    "City",
    "Education"
]
```

We can create numerical preprocessing:

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler

numeric_pipeline = Pipeline([
    ("imputer", SimpleImputer(
        strategy="median"
    )),
    ("scaler", StandardScaler())
])
```

Meaning:

```text
numerical data
      ↓
fill missing values
      ↓
standardize
```

---

# 38. Categorical Pipeline

```python
categorical_pipeline = Pipeline([
    ("imputer", SimpleImputer(
        strategy="most_frequent"
    )),
    ("encoder", OneHotEncoder(
        handle_unknown="ignore"
    ))
])
```

Meaning:

```text
categorical data
       ↓
fill missing categories
       ↓
one-hot encode
```

---

# 39. Combine Them

```python
from sklearn.compose import ColumnTransformer

preprocessor = ColumnTransformer([
    (
        "num",
        numeric_pipeline,
        numeric_features
    ),
    (
        "cat",
        categorical_pipeline,
        categorical_features
    )
])
```

Now:

```text
                    X
                    │
       ┌────────────┴─────────────┐
       ↓                          ↓
   Numerical                  Categorical
       │                          │
    median                   most frequent
   imputation                 imputation
       ↓                          ↓
   StandardScaler            OneHotEncoder
       │                          │
       └────────────┬─────────────┘
                    ↓
              Processed X
```

---

# 40. Why Pipelines Are So Important

Imagine you manually preprocess:

```text
training
testing
validation
production
```

It's very easy to accidentally do:

```text
fit scaler on test
fit encoder on test
calculate mean from entire dataset
```

A proper Pipeline helps enforce the correct workflow.

Eventually you'll have:

```python
pipeline = Pipeline([
    ("preprocessor", preprocessor),
    ("model", model)
])
```

Then:

```python
pipeline.fit(X_train, y_train)
```

The preprocessing and model training happen together.

---

# 41. The Big Rule You Should Memorize

We've now encountered this rule three times:

### Scaling

```text
fit → train
transform → train/test
```

### Encoding

```text
fit → train
transform → train/test
```

### Imputation

```text
fit → train
transform → train/test
```

Therefore the general rule is:

# 🔥 Learn preprocessing from training data only.

Then apply the learned transformation to unseen data.
