# Pandas — Part 2: Missing Data & Data Cleaning

Now we move from **"Pandas can display my data"** to **"Pandas can clean my real-world data."**

This is extremely important for ML because real datasets are rarely clean.

A dataset might look like:

```text
Name    Age    Salary    Experience
Ali     22     50000     1
Sara    NaN    70000     3
Ahmed   30     NaN       7
Zain    35     90000     NaN
```

`NaN` means something is missing.

Before training an ML model, we need to decide:

> **What should we do about that missing information?**

---

# 1. Why Does Missing Data Exist?

Missing values happen for many real-world reasons.

For example:

### Survey

A person didn't answer:

```text
Age → ?
```

### Sensors

A sensor stopped working:

```text
Temperature → ?
```

### Database

A field wasn't required:

```text
Salary → NULL
```

### Data collection error

Something failed during extraction.

### Different datasets

One dataset contains:

```text
Age
Salary
Experience
```

Another contains:

```text
Age
Salary
```

When combined, some experience values may be missing.

So missing data is **normal**.

---

# 2. Creating a Dataset with Missing Values

Let's create one.

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "Name": ["Ali", "Sara", "Ahmed", "Zain", "Hina"],
    "Age": [22, np.nan, 30, 35, 28],
    "Salary": [50000, 70000, np.nan, 90000, 65000],
    "Experience": [1, 3, 7, np.nan, 4]
})
```

It looks like:

```text
    Name   Age   Salary   Experience
0    Ali   22    50000       1
1   Sara   NaN   70000       3
2  Ahmed   30    NaN         7
3   Zain   35    90000      NaN
4   Hina   28    65000       4
```

---

# 3. What is `NaN`?

`NaN` means:

> **Not a Number**

But in Pandas, it is commonly used to represent missing numerical data.

```python
np.nan
```

creates a NaN.

You may also encounter:

```text
None
NaN
NA
NULL
```

depending on where your data comes from.

Pandas tries to represent missing values consistently.

---

# 4. Finding Missing Values

The first question should be:

> **Where are my missing values?**

Use:

```python
df.isna()
```

You'll get something like:

```text
    Name    Age   Salary   Experience
0  False  False   False      False
1  False   True   False      False
2  False  False   True       False
3  False  False   False       True
4  False  False   False      False
```

`True` means:

> This value is missing.

---

# 5. Count Missing Values

This is much more useful.

```python
df.isna().sum()
```

Result:

```text
Name           0
Age            1
Salary         1
Experience     1
```

Now you immediately know:

```text
Age         → 1 missing
Salary      → 1 missing
Experience  → 1 missing
Name        → 0 missing
```

---

# 6. Why Does `.sum()` Work?

This is the same NumPy idea we learned earlier.

Remember:

```text
True  → 1
False → 0
```

So:

```python
df.isna()
```

produces:

```text
False
True
False
False
False
```

and:

```python
.sum()
```

counts:

```text
0 + 1 + 0 + 0 + 0 = 1
```

This is a great example of your NumPy knowledge carrying over into Pandas.

---

# 7. Percentage of Missing Values

Suppose your dataset has 100,000 rows.

You don't just want:

```text
Age → 500 missing
```

You may want:

> What percentage is missing?

Use:

```python
df.isna().mean() * 100
```

For example:

```text
Age           10.2%
Salary         3.1%
Experience     7.5%
```

This becomes useful when deciding whether to remove or impute a column.

---

# 8. Find Rows Containing Missing Values

Suppose you want to see the actual problematic rows.

```python
df[df.isna().any(axis=1)]
```

Let's understand this.

### First:

```python
df.isna()
```

finds missing cells.

### Then:

```python
.any(axis=1)
```

asks:

> Does this row contain **at least one** missing value?

So you might get:

```text
    Name   Age   Salary   Experience
1   Sara   NaN   70000       3
2  Ahmed   30    NaN         7
3   Zain   35    90000      NaN
```

This is extremely useful.

---

# 9. `axis=1` Again

You already learned this in NumPy.

Here:

```python
df.isna().any(axis=1)
```

means:

> For each row, check whether **any column** contains a missing value.

Compare:

```python
df.isna().any(axis=0)
```

This asks:

> For each column, does **any row** contain a missing value?

So:

```text
axis=0 → investigate columns
axis=1 → investigate rows
```

---

# 10. Removing Missing Rows

The simplest solution is:

```python
df.dropna()
```

This removes rows containing missing values.

Our dataset:

```text
Ali     22    50000    1
Sara    NaN   70000    3
Ahmed   30    NaN      7
Zain    35    90000    NaN
Hina    28    65000    4
```

becomes:

```text
Ali     22    50000    1
Hina    28    65000    4
```

because those are the only complete rows.

---

# 11. Be Careful with `dropna()`

You might think:

> Great! I'll just remove all rows with missing data.

But imagine:

```text
1,000,000 rows
```

and only:

```text
2% missing
```

Dropping every affected row may throw away useful information.

Even worse:

```text
1,000,000 rows
80% have one missing value
```

Now `dropna()` could destroy most of your dataset.

Therefore:

> **Don't automatically delete missing data. Understand it first.**

---

# 12. Remove Columns with Too Much Missing Data

Sometimes the problem is a column.

Imagine:

```text
Column          Missing
Age               2%
Salary            1%
Experience        5%
Middle_Name      90%
```

Maybe `Middle_Name` isn't useful anyway.

You could remove it:

```python
df = df.drop(columns=["Middle_Name"])
```

This is often better than trying to fill 90% of its values.

---

# 13. Filling Missing Values

Instead of deleting data, we can **impute** it.

Imputation means:

> Replace missing values with a reasonable estimate.

For example:

```text
Age:
22
NaN
30
35
28
```

Maybe replace the missing age with the average.

---

# 14. Fill with Mean

Calculate:

```python
mean_age = df["Age"].mean()
```

Then:

```python
df["Age"] = df["Age"].fillna(mean_age)
```

Now the missing age is replaced with the mean age.

A shorter version:

```python
df["Age"] = df["Age"].fillna(
    df["Age"].mean()
)
```

---

# 15. Why Mean?

Suppose:

```text
Age = [20, 22, 24, NaN, 26]
```

The known values are centered around roughly:

```text
23
```

So replacing the missing value with the mean is a reasonable simple strategy.

But it isn't always appropriate.

---

# 16. Median Imputation

Consider:

```text
Salary:

30,000
35,000
40,000
45,000
5,000,000
NaN
```

The `5,000,000` is an extreme outlier.

The mean could be heavily distorted.

In such cases, the **median** can be more robust.

```python
df["Salary"] = df["Salary"].fillna(
    df["Salary"].median()
)
```

Remember:

```text
Mean   → sensitive to outliers
Median → more robust to outliers
```

This is an important ML concept.

---

# 17. Mode

For categorical data:

```text
Education

BS
MS
BS
BS
NaN
```

You could use the most common category:

```python
df["Education"] = df["Education"].fillna(
    df["Education"].mode()[0]
)
```

The mode is:

> The most frequently occurring value.

So:

```text
BS
```

would replace the missing value.

---

# 18. Choosing Mean vs Median vs Mode

A simple mental table:

| Data                        | Common strategy                        |
| --------------------------- | -------------------------------------- |
| Numerical, fairly symmetric | Mean                                   |
| Numerical, skewed/outliers  | Median                                 |
| Categorical                 | Mode                                   |
| Missingness is meaningful   | Consider a separate category/indicator |
| Extremely high missingness  | Consider dropping feature              |

But this isn't a universal rule.

The correct approach depends on the dataset and the reason values are missing.

---

# 19. Forward Fill

Sometimes data is sequential.

For example, sensor readings:

```text
Time    Temperature
10:00      25
10:01      25.2
10:02      NaN
10:03      25.5
```

You might want to carry the previous value forward:

```python
df["Temperature"] = df["Temperature"].ffill()
```

Conceptually:

```text
25.0
25.2
NaN
25.5
```

becomes:

```text
25.0
25.2
25.2
25.5
```

This can make sense for time-series data, depending on the situation.

---

# 20. Backward Fill

Similarly:

```python
df["Temperature"] = df["Temperature"].bfill()
```

means:

> Fill the missing value using the next available value.

So:

```text
25.0
25.2
NaN
25.5
```

becomes:

```text
25.0
25.2
25.5
25.5
```

Again, this is particularly relevant to sequential/time-series data.

---

# 21. Important ML Warning: Data Leakage

This is **very important**.

Suppose you're building a model.

You split:

```text
Training data
Testing data
```

You calculate:

```python
mean = entire_dataset["Age"].mean()
```

and use that mean to fill missing values in both datasets.

This can cause **data leakage**.

Why?

Because information from the test set has influenced your preprocessing.

Instead:

```text
Training set
    ↓
calculate mean
    ↓
use that mean to transform training set
    ↓
use SAME training mean to transform test set
```

This is a fundamental ML principle.

Later, when we study `scikit-learn` pipelines, we'll do this properly.

For now, remember:

> **Learn preprocessing parameters from training data, not from the entire dataset.**

---

# 22. Duplicates

Missing values aren't the only problem.

Datasets can contain duplicate rows.

Example:

```text
Name    Age    Salary
Ali     22     50000
Sara    25     70000
Ali     22     50000
```

The third row is a duplicate.

Check:

```python
df.duplicated()
```

You might get:

```text
False
False
True
```

---

# 23. Count Duplicates

```python
df.duplicated().sum()
```

If the result is:

```text
1
```

you have one duplicate row.

---

# 24. Remove Duplicates

```python
df = df.drop_duplicates()
```

Now the duplicate is gone.

---

# 25. Duplicate Based on Specific Columns

Sometimes two rows aren't completely identical, but you consider them duplicates based on certain fields.

For example:

```text
Customer_ID
```

should be unique.

You can use:

```python
df.duplicated(
    subset=["Customer_ID"]
)
```

And:

```python
df = df.drop_duplicates(
    subset=["Customer_ID"]
)
```

This is very useful in real datasets.

---

# 26. Data Types

Another major cleaning task is fixing incorrect data types.

Suppose:

```text
Age
"20"
"25"
"30"
```

Pandas might interpret them as strings/object rather than numbers.

Check:

```python
df.dtypes
```

If you see:

```text
Age    object
```

that's suspicious if Age is supposed to be numerical.

---

# 27. Convert to Numeric

You can use:

```python
df["Age"] = pd.to_numeric(
    df["Age"]
)
```

Now:

```text
Age → int/float
```

depending on the data.

---

# 28. What If There Are Bad Values?

Suppose:

```text
Age

20
25
unknown
30
```

Trying:

```python
pd.to_numeric(df["Age"])
```

may fail.

You can tell Pandas:

> If something cannot be converted, turn it into NaN.

```python
df["Age"] = pd.to_numeric(
    df["Age"],
    errors="coerce"
)
```

Now:

```text
20
25
NaN
30
```

Then you can handle the missing value.

This is a very useful real-world cleaning technique.

---

# 29. String Cleaning

Real datasets often contain messy strings.

Suppose:

```text
City

"Karachi"
" karachi"
"KARACHI"
"Karachi "
```

Technically these can be interpreted as different strings.

Pandas provides string operations.

```python
df["City"] = df["City"].str.strip()
```

`strip()` removes leading/trailing whitespace.

---

# 30. Lowercase

You could standardize:

```python
df["City"] = df["City"].str.lower()
```

Then:

```text
Karachi
KARACHI
karachi
```

become:

```text
karachi
karachi
karachi
```

This is useful when cleaning categorical variables.

---

# 31. Replace Values

Suppose:

```text
Gender

M
Male
m
F
Female
```

You might standardize them:

```python
df["Gender"] = df["Gender"].replace({
    "M": "Male",
    "m": "Male",
    "F": "Female"

```

Now the categories are more consistent.

# 32. Detecting Impossible Values

Data can be missing without being `NaN`.

Imagine:

```text
Age

22
25
-5
30
200
```

There are no missing values.

But:

```text
-5
200
```

are suspicious/impossible ages in many contexts.

Pandas lets you filter them:

```python
df[df["Age"] < 0]
```

or:

```python
df[df["Age"] > 100]
```

This is called **data validation**.

# 33. Real-World ML Cleaning

Suppose you're predicting salary.

Your dataset:

```text
Age | Experience | Salary
--------------------------------
22  | 1           | 45000
25  | 3           | NaN
-2  | 5           | 70000
30  | NaN         | 95000
35  | 10          | 90000
35  | 10          | 90000
```

We have several problems:

```text
NaN             → missing value
-2              → invalid value
duplicate row   → duplicate
```

A proper cleaning workflow might be:

```text
Raw Data
   ↓
Inspect
   ↓
Find missing values
   ↓
Find duplicates
   ↓
Check invalid values
   ↓
Fix data types
   ↓
Handle missing values
   ↓
Remove duplicates
   ↓
Validate again
   ↓
Clean Dataset
```

---

# 34. A Complete Small Cleaning Example

Let's build one.

```python
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "Name": ["Ali", "Sara", "Ahmed", "Zain", "Zain"],
    "Age": [22, np.nan, -5, 35, 35],
    "Salary": [50000, 70000, np.nan, 90000, 90000],
    "Experience": [1, 3, 7, np.nan, np.nan]
})
```

### Step 1 — Inspect

```python
df.info()
```

---

### Step 2 — Missing values

```python
df.isna().sum()
```

---

### Step 3 — Duplicates

```python
df.duplicated().sum()
```

---

### Step 4 — Invalid age

```python
df[df["Age"] < 0]
```

---

### Step 5 — Replace invalid ages with NaN

```python
df.loc[df["Age"] < 0, "Age"] = np.nan
```

Now the invalid `-5` has become missing.

---

### Step 6 — Fill numerical missing values

For example:

```python
df["Age"] = df["Age"].fillna(
    df["Age"].median()
)
```

and:

```python
df["Salary"] = df["Salary"].fillna(
    df["Salary"].median()
)
```

---

### Step 7 — Handle duplicates

```python
df = df.drop_duplicates()
```

---

### Step 8 — Inspect again

```python
df.info()
```

and:

```python
df.describe()
```

This is a basic but realistic cleaning pipeline.

---

# 35. `loc` Becomes Very Powerful Here

Remember:

```python
df.loc[condition, column]
```

You can use this to modify specific values.

For example:

```python
df.loc[df["Age"] < 0, "Age"] = np.nan
```

Read it as:

> Find rows where Age is less than zero, and in the Age column, replace those values with NaN.

This pattern is extremely useful.

---

# 36. `query()`

Pandas also provides:

```python
df.query()
```

Instead of:

```python
df[df["Age"] > 25]
```

you can write:

```python
df.query("Age > 25")
```

For multiple conditions:

```python
df.query(
    "Age > 25 and Salary > 70000"
)
```

This can make some filtering operations more readable.

However, I recommend becoming very comfortable with:

```python
df[condition]
```

and:

```python
df.loc[condition]
```

first.

# 37. A Very Important Principle

Don't confuse:

```text
Missing
```

with:

```text
Zero
```

Suppose:

```text
Study_Hours = NaN
```

This means:

> We don't know how many hours the student studied.

Whereas:

```text
Study_Hours = 0
```

means:

> The student studied zero hours.

These are completely different.

Similarly:

```text
Salary = NaN
```

doesn't mean:

```text
Salary = 0
```

Never casually replace missing values with zero unless zero is genuinely the correct meaning.

---

# 38. Another Important Principle: Missingness Can Be Information

Imagine a medical survey:

```text
Income = NaN
```

Maybe people with certain circumstances were more likely not to report income.

Or:

```text
Credit_History = NaN
```

might indicate that the person has no credit history.

Sometimes:

> **The fact that a value is missing is itself informative.**

You can create a missing indicator:

```python
df["Salary_missing"] = df["Salary"].isna()
```

Before filling the salary.

Now:

```text
Salary     Salary_missing
50000      False
70000      False
NaN        True
90000      False
```

This can sometimes be useful as a feature.

```text
          │          │          │

                     ↓

                     │
          ┌──────────┼──────────┐

                     │

                VALID DATA
                     │
                     ↓

                     │

```

This is the mindset you want.

# 42. One Important Thing Before We Continue

There's a concept we haven't covered yet that is **absolutely central to data science**:

# `groupby()`

Imagine your dataset contains:

```text
Department    Employee    Salary
Engineering  Ali          100000
Engineering  Sara         120000
Sales        Ahmed         70000
Sales        Zain          80000
HR           Hina          60000
```

You might ask:

> What is the average salary of each department?

Pandas can answer:

```python
df.groupby("Department")["Salary"].mean()
```

Result:

```text
Engineering    110000
Sales           75000
HR              60000
```

This is the beginning of **group-based analysis**, and it becomes extremely powerful.
