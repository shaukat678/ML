# Pandas for ML — Part 10: Feature Selection 🎯

We've just learned **Feature Engineering**:

> Create useful features from existing data.

Now comes the opposite question:

> **Which features should we keep, and which should we remove?**

This is **Feature Selection**.

---

# 1. The Big Picture

Imagine you start with:

```text
Dataset
│
├── Age
├── Salary
├── City
├── Height
├── Weight
├── Random_Number
├── ID
├── Noise
├── Distance
├── Traffic
├── ...
└── 500 more columns
```

You don't necessarily want all of them.

Feature selection tries to find:

```text
500 features
      ↓
 useful features
      ↓
 30 features
```

The goal isn't simply:

> "Use fewer features."

The goal is:

> **Keep information that helps prediction and remove information that doesn't.**

---

# 2. Why Do We Remove Features?

There are several reasons.

### 1. Irrelevant features

Suppose you're predicting house price:

```text
Area
Bedrooms
Location
Wall_Color
```

Maybe `Wall_Color` provides almost no useful information.

---

### 2. Redundant features

Suppose you have:

```text
Height_cm
Height_m
```

These contain essentially the same information.

Keeping both isn't useful.

---

### 3. Noise

Suppose:

```text
Random_Number
```

is completely unrelated to your target.

It can make the model learn meaningless patterns.

---

### 4. Computational cost

Fewer features can mean:

```text
less memory
less computation
faster training
```

---

### 5. Overfitting

Too many noisy features can make some models memorize training data rather than learning general patterns.

---

# 3. A Very Important Distinction

Don't confuse:

### Feature Engineering

```text
Existing features
      ↓
create new features
```

with:

### Feature Selection

```text
Existing features
      ↓
choose useful features
```

and:

### Dimensionality Reduction

```text
Many features
      ↓
transform them into fewer new dimensions
```

We'll discuss dimensionality reduction later.

---

# 4. First Tool: Correlation

Let's say:

```text
Study_Hours
Exam_Score
```

You might find:

$$
r = 0.85
$$

This suggests a strong positive linear relationship.

As study hours increase, exam score tends to increase.

In Pandas:

```python
df["Study_Hours"].corr(
    df["Exam_Score"]
)
```

---

# 5. `df.corr()`

You can calculate correlations between numerical columns:

```python
df.corr(numeric_only=True)
```

You might get:

```text
               Age   Salary   Experience
Age           1.00    0.20       0.30
Salary        0.20    1.00       0.85
Experience    0.30    0.85       1.00
```

The values are between:

$$
-1 \leq r \leq 1
$$

---

# 6. Understanding Correlation

Roughly:

```text
+1
│
│   Strong positive
│
 0 ───────────────
│
│   Strong negative
│
-1
```

Examples:

```text
r ≈ +1
```

means strong positive linear relationship.

```text
r ≈ -1
```

means strong negative linear relationship.

```text
r ≈ 0
```

means little or no **linear** relationship.

---

# 7. Important: Correlation ≠ Causation

Suppose:

```text
Ice Cream Sales ↑
Drowning Cases ↑
```

They may be correlated.

Does eating ice cream cause drowning?

Obviously not.

A third variable:

```text
Temperature
```

could affect both.

So correlation tells us:

> **Variables move together.**

It does not prove:

> **One causes the other.**

---

# 8. Correlation With the Target

Suppose:

```text
Target = House_Price
```

You can inspect:

```python
df.corr(numeric_only=True)["House_Price"]
```

Maybe:

```text
Area             0.80
Bedrooms         0.55
Age             -0.40
Random_Number    0.01
```

This gives you an initial idea about which numerical variables have a linear relationship with the target.

---

# 9. But Don't Do This:

> "Correlation is low, therefore remove the feature."

That's a mistake.

Why?

Because correlation measures **linear** relationship.

Imagine:

$$
y=x^2
$$

There is a strong relationship between `x` and `y`, but Pearson correlation can be close to zero in symmetric situations.

So:

```text
Low correlation
      ≠
No predictive value
```

---

# 10. Example of a Nonlinear Relationship

Imagine:

```text
X:

-3
-2
-1
0
1
2
3
```

and:

```text
Y = X²
```

Then:

```text
X → Y

-3 → 9
-2 → 4
-1 → 1
 0 → 0
 1 → 1
 2 → 4
 3 → 9
```

There is clearly a relationship.

But the relationship isn't linear.

This is why feature selection should not rely entirely on correlation.

---

# 11. Correlation Between Features

Now we encounter another important problem:

# Multicollinearity

Suppose:

```text
Age
Years_of_Experience
```

are strongly correlated.

Maybe:

```text
Age ↑
Experience ↑
```

So:

```python
df["Age"].corr(
    df["Years_of_Experience"]
)
```

might produce:

```text
0.90
```

These two features contain overlapping information.

---

# 12. Why Is Multicollinearity a Problem?

Consider a linear model:

$$
Salary =
\beta_0 +
\beta_1 Age +
\beta_2 Experience
$$

If:

```text
Age
```

and:

```text
Experience
```

are almost telling the model the same thing, it becomes difficult to determine:

> How much of the effect should be attributed to Age?

and:

> How much to Experience?

This can make coefficients unstable and difficult to interpret.

---

# 13. Important Nuance

Multicollinearity is especially important for models where coefficients matter, such as:

* Linear Regression
* Logistic Regression

Tree-based models often tolerate correlated features better, although redundant features can still affect efficiency, importance interpretation, and sometimes generalization.

So feature selection depends partly on the model you're using.

---

# 17. Variance-Based Selection

Here's another simple idea.

Suppose:

```text
Feature A:

1
1
1
1
1
1
```

There is almost no variation.

It may provide little information.

We can measure:

```python
df.var()
```

A feature with extremely low variance may be a candidate for removal.

---

# 18. `VarianceThreshold`

Scikit-learn provides:

```python
from sklearn.feature_selection import VarianceThreshold
```

Example:

```python
selector = VarianceThreshold(
    threshold=0.01
)
```

Then:

```python
X_new = selector.fit_transform(X)
```

This removes features whose variance is below the specified threshold.

---

# 19. But Low Variance Doesn't Automatically Mean Useless

Suppose:

```text
Fraud = 1
```

occurs only:

```text
0.1%
```

of the time.

A feature may have low variance but still be useful for detecting fraud.

So:

> Variance is a filtering tool, not proof that a feature is useless.

# 20. Feature Selection Methods

Feature selection is commonly divided into three categories:

```text
Feature Selection
│
├── Filter Methods
│
├── Wrapper Methods
│
└── Embedded Methods
```

This classification is important.

---

# 21. Filter Methods

Filter methods evaluate features **before** training a particular model.

Examples:

```text
Correlation
Variance
Chi-square
Mutual Information
ANOVA
```

Think:

> "Let's inspect the features themselves and filter out weak ones."

---

# 22. Correlation as a Filter

For a regression problem:

```python
correlations = (
    df.corr(numeric_only=True)["target"]
)
```

You can inspect which features have stronger relationships with the target.

But remember the limitation:

> Correlation mainly captures linear relationships.

---

# 23. Mutual Information

Mutual information is more flexible.

Conceptually:

> How much information does feature X provide about target Y?

Unlike Pearson correlation, mutual information can detect some nonlinear relationships.

Scikit-learn:

```python
from sklearn.feature_selection import mutual_info_regression
```

For classification:

```python
from sklearn.feature_selection import mutual_info_classif
```

You don't need to master the mathematics yet.

Just remember:

```text
Correlation
→ linear relationship

Mutual Information
→ broader dependency
```

---

# 24. Wrapper Methods

Wrapper methods actually use a model to evaluate subsets of features.

Imagine:

```text
100 features
```

Try:

```text
50 features
```

Train model.

Then:

```text
40 features
```

Train model.

Then:

```text
30 features
```

Train model.

And compare performance.

The model is effectively helping answer:

> "Which subset works best?"

---

# 25. Why Are Wrapper Methods Expensive?

Because they may train the model many times.

If you have:

```text
1000 features
```

testing many subsets becomes computationally expensive.

So wrapper methods can be powerful but costly.

---

# 26. RFE

One famous wrapper method:

# Recursive Feature Elimination

```python
from sklearn.feature_selection import RFE
```

Conceptually:

```text
100 features
     ↓
train model
     ↓
remove least useful feature(s)
     ↓
99 features
     ↓
train again
     ↓
...
     ↓
20 features
```

It recursively removes features.

---

# 27. Embedded Methods

Embedded methods perform feature selection **during model training**.

Examples:

```text
Lasso
Decision Trees
Random Forests
Gradient Boosting
```

These methods can naturally provide information about feature usefulness.

---

# 28. Lasso Feature Selection

Remember linear regression:

$$
y =
\beta_0+
\beta_1x_1+
\beta_2x_2+
...
$$

Lasso adds an L1 penalty.

Conceptually:

$$
Loss +
\lambda \sum |\beta_i|
$$

The penalty encourages some coefficients to become exactly:

$$
0
$$

So:

```text
Feature A → coefficient 0.83
Feature B → coefficient 0.41
Feature C → coefficient 0
Feature D → coefficient 0
```

Features with zero coefficients can effectively be discarded.

---

# 29. Decision Trees

Tree-based models can also tell us which features were useful for making splits.

For example:

```python
model.feature_importances_
```

might produce:

```text
Distance       0.42
Traffic        0.31
Passengers     0.15
Age            0.07
Random         0.05
```

You can then investigate whether the low-importance features are useful enough to keep.

---

# 30. ⚠️ Feature Importance Isn't Absolute Truth

Suppose:

```text
Distance = 0.42
Traffic = 0.31
```

You shouldn't automatically conclude:

> Distance is fundamentally 42% responsible for the target.

Feature importance is **model-specific** and depends on the dataset, model, and importance method.

Also, correlated features can split importance between themselves.

---

# 31. Your Earlier Question: "Distance Dominates"

You previously raised a very good concern:

> What if distance dominates the model?

There are several different meanings of "dominates."

### Case 1: Distance has a large numerical scale

Example:

```text
Distance = 500
Traffic = 5
```

For some models, scaling matters.

Standardization can help models such as linear models, SVMs, and neural networks.

---

### Case 2: Distance genuinely contains strong predictive information

Then a large importance may simply be correct.

You shouldn't remove it merely because it is important.

---

### Case 3: Distance is redundant

Maybe:

```text
Distance
Travel_Time
Route_Length
```

are highly related.

Then you need to investigate redundancy.

---

### Case 4: Distance causes leakage

Suppose your feature was calculated using information that wouldn't be available at prediction time.

Then it must be removed.

So:

> **"Dominates" isn't automatically a problem. We need to understand why.**

---

# 32. Scaling ≠ Feature Selection

This is another important distinction.

Suppose:

```text
Distance = 1000
Traffic = 5
```

Standardization changes:

```text
Distance
Traffic
```

to comparable scales.

It does **not** remove Distance.

Feature selection might remove Distance.

So:

```text
Scaling
→ changes representation

Selection
→ chooses features
```

---

# 33. Feature Selection Must Be Evaluated

Suppose you have:

```text
Model A:
100 features
Accuracy = 91%

Model B:
30 features
Accuracy = 92%
```

Great!

You've reduced the feature count and improved performance.

But perhaps:

```text
Model C:
10 features
Accuracy = 91.8%
```

Now you have a tradeoff.

Maybe 10 features are preferable because the model is:

* simpler
* faster
* easier to explain

This is why there isn't always a single "correct" number of features.

---

# 34. The Correct Way to Compare

Use cross-validation.

Conceptually:

```text
Feature Set A
     ↓
Cross-validation
     ↓
Average score

Feature Set B
     ↓
Cross-validation
     ↓
Average score
```

Then compare.

Don't decide based only on training accuracy.

---

# 35. 🚨 Data Leakage Again

Suppose you have:

```text
1000 rows
```

You calculate feature-target correlations using **all 1000 rows**.

Then:

```text
split into train/test
```

You've allowed test-set information to influence your feature selection.

That can cause optimistic evaluation.

The safer workflow is:

```text
RAW DATA
   ↓
TRAIN / TEST SPLIT
   ↓
Feature selection learned from TRAIN
   ↓
Apply selection to TEST
   ↓
Evaluate
```

For robust model development, feature selection should generally happen **inside the cross-validation/training pipeline** when the selection is learned from data.

---

```text
           ┌───────────┴───────────┐

           │                       │

           │                 ↓           ↓

```

# 38. A Very Important Mindset

Don't ask:

> "How many features can I put into my model?"

Ask:

> **"What information does each feature provide?"**

For every feature, you should ideally be able to explain:

```text
What does it represent?
Why might it predict y?
When is it available?
Is it redundant?
Could it leak information?
Does it improve validation performance?
```

That is how an ML engineer thinks about features.
